# receiverproxy web app

Dev: `pnpm install`, `scripts/build-wasm.sh` (optional; without it the Builder reports the module is not built and the Panels downloads fail with the same message), then `pnpm dev` (SvelteKit on http://localhost:5173, API proxied to a daemon on 127.0.0.1:7120; `VITE_RXP_MOCK=1 pnpm dev` uses canned cards and a simulated job).
Build: `pnpm build` runs `svelte-check` and builds the site with adapter-cloudflare into `.svelte-kit/cloudflare` (`pnpm deploy` is `wrangler deploy` to receiverproxy.com, `wrangler.jsonc`); `pnpm build:embed` sets `ADAPTER=static` and writes `build-static/`, which `daemon` embeds on its next `cargo build`. `/`, `/panels`, `/panels/[name]`, `/cards`, `/cards/[model]`, `sitemap.xml` and `robots.txt` are prerendered from `config/` at build time by `src/lib/server/config.ts` (node, smol-toml, no WASM); `/gallery` and `/gallery/[name]` are prerendered 301 redirects to `/panels`; `/builder`, `/wall`, `/control` and their sub-pages render on the client only and are `noindex`.
Test: `pnpm test` runs `tests/*.test.ts` with node's test runner (no dependencies; node 22.18 or later strips the types): the token fragment and the config loader against the repository's `config/` files.
Types: `src/api/types.ts` is generated by `cargo test -p daemon --features ts` from the Rust request and response structs; the test fails and rewrites the file when it is stale. Do not edit it by hand. Routes call `src/api/ops.ts` only; it binds pure operations to the WASM module and card operations to the daemon (`ops.card` is null while the daemon is absent). `pnpm dev` against a running daemon needs its token: open `http://localhost:5173/#token=...` with the value `rxp ui` printed, or type it into the banner under the top bar.
Contract: `../docs/ui.md`; design: `../docs/ui-design.md`.
